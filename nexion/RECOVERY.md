# NEXION v0.2.4 — 로컬 노드 재시작·철회 로그 손상 감지 (2026-11-14)

## 이번 실험의 작은 목표

기존 분산 동의 실험은 철회 이벤트와 노드 커서를 RAM에만 저장하여 프로세스를 재시작하면 상태가 사라졌습니다. 이번에는 **선택형 로컬 SQLite 철회 저널**을 추가하고 장애 주입 테스트로 다음을 확인합니다.

- 사건 번호(1, 2, 3...) + 해시 연결 + 현재 head 체크포인트로 이벤트 누락·순서 역행·본문 변조 감지
- 노드별 마지막 처리 이벤트 번호/해시를 저장한 뒤 프로세스 재시작 시 복구
- 동의 철회 기록을 DB에 남기기 전 프로그램이 중단되면 `pending_participant` 기록이 남아 재시작 후 **전송·큐잉 거부(fail closed)**
- 수신자/발신자가 철회했거나, 권한 확인이 불가능하거나, 저널 신뢰가 무너지면 전송 거부
- 재시작 시 RAM 메시지 대기열을 지워서 이전 평문을 재전송하지 않음 (대기 메시지 전달의 영속성은 구현하지 않음)

## 실행

Python 3.9 이상, 추가 패키지 없음. 이 폴더에서:

```bash
python -m unittest discover -s tests -v
python -m unittest discover -s tests -p 'test_revocation_journal.py' -v
```

새 기능은 기존 `DistributedConsentLab` 생성자에서 선택적으로만 켜집니다.

```python
from nexion.distributed_consent import DistributedConsentLab
# ConsentStore 자체는 기존 동의 정보를 저장하는 별개의 로컬 DB입니다.
lab = DistributedConsentLab(store, ["node-a", "node-b"], journal_path="revocations.sqlite3")
# ... 오프라인 임무/동의 실험 ...
lab.close()  # store.close()는 호출자가 별도로 수행
```

`journal_path`를 주지 않으면 v0.2.3 방식의 메모리 로그가 그대로 작동합니다.

## 장애 시험과 기대 동작

| 고장 조건 | 기대 결과 |
|---|---|
| 두 번 철회 후 노드/권한 DB 재시작 | 마지막 커서와 관측된 철회 ID 복구 |
| 맨 끝 이벤트 삭제 | head 및 로그 불일치 감지, 새 전송/큐잉 거부 |
| 중간 이벤트 삭제 | 연속 번호 및 연결 해시 위반 감지, 전송 거부 |
| 이벤트 참여자 ID/해시 변조 | 해시 검증 실패, 전송 거부 |
| 노드 커서가 미래를 가리키거나 해시 불일치 | 재시작 거부/전송 거부 |
| 철회 예약 직후 가상 크래시 | 미완료 의도 감지, 재시작 거부 |
| 잘못된 철회 토큰 | DB 철회 롤백·예약 정리, 기존 동의 유지 |
| 휘발성 대기열을 가진 노드 재시작 | 대기열 비움, 중복 전달 없음 |

## 한계 (매우 중요)

1. 해시는 **비우발적 손상 감지** 용도입니다. 공격자가 저널과 head를 함께 바꾸면 검증을 우회할 수 있습니다. 외부 서명·검증된 앵커가 없습니다.
2. 두 개의 서로 다른 SQLite DB에 걸친 진짜 원자적 트랜잭션은 구현하지 않았습니다. `begin_withdrawal` / `finish_withdrawal` 사이에 오류가 나면 차단 후 운영자 점검이 필요하며 자동 복구하지 않습니다.
3. 저널 파일 전체가 삭제되고 새 파일이 만들어지면 이를 탐지할 별도 신뢰 앵커가 없습니다. 기존 DB에서 head만 사라진 경우는 차단합니다.
4. 이벤트 기록은 이 실험의 `lab.withdraw()` 경로에 한정됩니다. `store.withdraw()`를 직접 사용한 철회는 저장소의 실제 상태를 통해 전송 시 재검증하지만 저널 이벤트에는 남지 않습니다.
5. 연결이 끊긴 노드의 RAM에 이미 있던 평문은 노드가 복귀하기 전까지 중앙에서 지울 수 없습니다.
6. 네트워크 전송·실제 다중 서버 합의·지속 메시지 큐·실명 신원 검증·설비 연결·원격 제어·제작 명령을 구현하거나 실증하지 않았습니다.
7. 로컬 단일 프로세스 시뮬레이터입니다. 가용성/안전성/의식의 증거가 아닙니다.

## 후속 소규모 연구

- 저널과 권한 DB의 불일치 복구를 **검증 가능한 관리자 승인 절차**로 설계
- 독립 검증 앵커 및 무결성 검사 주기 구현 (위협 모델 명시)
- 프로세스 강제 종료, 디스크 FULL, SQLite journal_mode 변형을 포함한 장애 주입 확대
