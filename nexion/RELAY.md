# NEXION 오프라인 참여자 통신 시뮬레이터 — 2026-11-11

## 이번 단계의 목표
NEXION의 참여자 간 통신에서 **동의 철회·통신 단절·재전송** 조건을
온라인 서버 없이 재현하고 검증합니다. 구현체: `nexion/relay.py`.
기존 `consent.py`의 로컬 승인/철회 정책을 재사용하며, 외부 네트워크 호출을 하지 않습니다.

## 확인 가능한 동작
- 보내는 사람과 받는 사람 모두 `peer_chat` 범위를 승인한 경우에만 메시지를 큐에 추가
- 회선 단절(`link_available=False`) 동안 큐 보관, 복구 시 로컬 SQLite 받은 편지함으로 전달
- 발신자별 `client_id`를 중복 방지 키로 사용; 재시도로 같은 메시지가 중복 저장되지 않음
- 메시지 본문 또는 상대가 달라진 중복 ID는 거부 (본문 비교에는 메모리 내 임의 키 HMAC 사용)
- 전송 전 **양쪽의 현 시점 참여 동의** 재확인
- 동의 철회/TTL 만료 시 대기 중인 메시지 본문 삭제, 그 이후 전송 차단
- TTL 1초~24시간, 개별 발신자 큐 100건, 전체 추적 키 500건 (기본값)
- 액세스 토큰을 큐/감사 로그에 저장하지 않음, 다른 발신자의 메시지 상태 조회 차단

## 재현 방법
Python 3.9 이상, 외부 패키지 불필요:

```bash
cd nexion
python -m unittest discover -s tests -v
```

검증: 기존 32개 테스트 + 신규 18개 테스트 = 총 **50개 로컬 테스트 통과**
(2026-11-11 개발 환경에서 실행. GitHub CI 자동 실행은 별도 확인 필요).

## 한계 및 안전 경계
이 구현은 **단일 프로세스의 오프라인 시뮬레이터**입니다. 인터넷 전송, 실시간 서버,
운영체제 간 통신, 장비 제어, 사람의 이메일/조직 신원 검증, E2E 암호화는 구현하지 않았습니다.

- 대기 메시지는 메모리에서 **평문**으로 보관하며 프로세스 종료 시 유실됩니다.
  보안 수준이 검증된 실서비스 데이터 저장소로 간주하면 안 됩니다.
- `OfflineRelay.withdraw(...)`로 동의 철회하면 큐를 즉시 정리합니다.
  기존 `ConsentStore.withdraw(...)`를 직접 호출했다면 다음
  `reconcile()` / `flush()` / `queue()` / `status()`
  호출 시 큐에서 삭제합니다. 철회 직후 완전 자동 정리/분산 합의는 아직 미지원입니다.
- 중복 ID와 처리 상태는 메모리에 남으며 최대 500개 도달 시 새 등록을 막습니다.
  만료된 처리 기록을 자동 회수하는 정책은 아직 구현하지 않았습니다.
- 예시 프로그램이 제공하는 등록 토큰은 실제 이메일 소유권 검증이 아닙니다.
- 외부 발송, 생산시설 연결, 주문, 제어, 물리적 제작은 **0회**입니다.
  사용자나 기관의 명시적 권한 없이 이를 실행하는 경로는 제공하지 않습니다.

## 다음 권장 단계
1. 동의 철회가 여러 노드에 전달되는 **오프라인 이벤트 로그/동기화 모델**을 설계하고
   철회 후 대기 메시지가 결코 전달되지 않는지 장애 주입으로 검증
2. 메시지 식별자 및 감사 기록 보존 기간 명세와 개인정보 최소화 테스트
3. 실제 사람을 연결하려면 별도 서비스/본인 확인/보안 심사/참여 동의가 선행되어야 함
