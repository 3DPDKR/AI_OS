# NEXION v0.2.5 — 독립 로컬 앵커 기반 저널 변조 탐지 (2026-11-15)

## 목표 / 위협 모델

기존 v0.2.4는 공격자가 journal_events와 journal_head를 동시에 재작성하면 내부 SHA-256 해시 사슬이 일관된 것으로 보일 수 있었습니다. 이번 실험은 **별도 파일 + 저널 외부에서 제공한 비밀키**로 저널의 커밋 상태를 HMAC-SHA256 인증하여 *한 파일만 변조하거나 과거 상태로 되돌리는 상황*을 차단합니다.

인증 대상: 저널 sequence, 해시 head, 진행 중 철회 의도(pending_participant), 노드별 checkpoint 목록의 정규화 SHA-256. 저널의 기존 행·커서 연속성 검사와 합쳐 확인합니다.

## 실행 — 오프라인 전용

```python
import secrets
from nexion.consent import ConsentStore
from nexion.distributed_consent import DistributedConsentLab

# 신규 저널에만 최초 적용. 아래 키는 예시로만 생성됩니다.
# 재시작 시에는 동일한 외부 비밀키를 재공급해야 합니다.
key = secrets.token_bytes(32)
store = ConsentStore('consents.sqlite3')
lab = DistributedConsentLab(store, ['node-a', 'node-b'],
    journal_path='revocations.sqlite3',
    anchor_path='separate-trusted-directory/anchor.json',
    anchor_key=key)
# ... 허가된 시뮬레이션 ...
lab.close()
store.close()
```

- 두 파일은 **서로 다른 파일**이어야 합니다. 앵커 경로의 부모 디렉터리는 미리 존재해야 합니다.
- anchor_key는 최소 32바이트이며 GitHub 소스 코드/로그/앵커 파일에 저장하지 않습니다. 실환경 키 보관·교체 절차는 별도 설계가 필요합니다.
- 존재하는 구버전 비앵커 저널에 앵커를 조용히 생성하지 않습니다. 신뢰된 점검 후 마이그레이션 설계가 필요합니다.
- 앵커 파일을 잃거나 비밀키가 다르면 **실행을 거부**합니다. 단순 삭제·재생성으로 자동 복구하지 않습니다.
- 기록 변경은 SQLite 커밋 뒤 파일 임시 쓰기/fsync/os.replace로 앵커를 갱신합니다. 두 파일 사이 **원자적 커밋이 아닙니다**. 갱신 사이 강제 종료 시 불일치로 보수적으로 중단합니다.

## 시험 항목

신규 단위 테스트 **16개**: 초기 생성, 정상 철회·커서 복원, 앵커 보존 상태의 단독 저널 롤백, 해시 사슬을 다시 계산한 유사 정상 조작, 임의 이벤트 추가, 커서 퇴행, 진행 중 철회 임의 삭제, 정상 pending 상태 재시작 차단, 앵커 삭제, 저널 재생성, 잘못된 키, MAC 변조, 설정 오류, 비앵커 저널 자동 편입 거부, 커밋/앵커 기록 사이 강제 오류, 비앵커 모드 회귀.

재현: `python -m unittest discover -s tests -v` (Python 3.9+ / 표준 라이브러리)

## 반드시 남는 한계

1. **독립 서버/하드웨어 서명 장치가 아닙니다.** 같은 컴퓨터에서 두 파일과 비밀키까지 탈취한 공격자를 방어하지 못합니다.
2. 이전에 유효하게 인증된 **앵커와 저널을 함께 롤백**하면 탐지하지 못합니다. 이 경우에는 별도 하드웨어 단조 카운터/원격 신뢰 로그가 필요합니다.
3. 인증 기록과 권한 DB는 다른 SQLite 파일입니다. 두 파일 사이 원자적 커밋은 제공하지 않습니다. 실패 시 관리자 조사 없이 자동 복구하지 않습니다.
4. 정전·디스크 오류·동시 다중 프로세스 등의 실물 고장에 대한 내구성/가용성은 검증하지 않았습니다. 무결성 불확실성은 전송 중지로 처리합니다.
5. 실제 네트워크·신원 인증·시설 연결·장비 제어·무인 구매·대량 메시지는 수행하지 않습니다.
