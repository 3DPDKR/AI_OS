# NEXION v0.2.2 — 오프라인 다중 노드 동의 철회 전파 실험

## 목표와 안전한 결론

두 개의 **모의 노드**가 각자 메시지 대기열과 철회 이벤트 커서를 갖는 환경에서,
네트워크 단절·중앙 권한 확인 장애·재접속·동의 철회 조건을 재현합니다.

이 모델은 철회 정보가 늦게 전파되더라도 **전달 시점의 권한 확인이 불가능하면
메시지를 보내지 않는(fail-closed)** 규칙을 사용합니다. 별도의 실시간 네트워크,
통신 서버, 실제 사람 계정, 생산설비 제어는 구현하지 않습니다.

## 구현

- `nexion/distributed_consent.py`: `DistributedConsentLab`와 모의 노드, 순번이 있는 동의 철회 이벤트 로그
- `tests/test_distributed_consent.py`: 연결 끊김, 오래된 로컬 복제본, 권한 서버 장애, 재연결, 다중 철회 회귀 테스트
- `nexion/consent.py`: 두 번째 참여자 철회에서 `UNIQUE constraint failed`가 발생하던 결함 수정. 기존에는 모든 철회 행의 `access_digest` 및 `withdrawal_digest`를 동일한 빈 문자열로 덮어썼습니다. 이제 철회 시 각각 **새 난수 기반 해시**로 변경하여, 기존 인증 토큰을 무효화하면서 UNIQUE 제약을 지킵니다.

## 실행

Python 3.9 이상, 외부 의존성 없음. 프로젝트 `nexion/` 폴더에서:

```sh
python -m unittest discover -s tests -v
```

기존 50개 + 신규 18개 = **총 68개 테스트** (실행 기록은 `TEST_RESULTS.txt` 참조).

## 안전/프라이버시 경계

1. `queue`, `flush`, `sync`는 연결 또는 현재 승인 상태를 검증할 수 없으면 차단합니다. 대기 중이던 메시지도 권한 서버가 끊기면 전송하지 않습니다.
2. 운영자가 철회를 승인하면 중앙 모의 저장소에서는 즉시 거부합니다. 통신이 끊긴 복제 노드의 메모리에는 **기존 평문 메시지가 남을 수 있으며, 복구 후 동기화할 때 삭제**됩니다. 물리적으로 오프라인인 노드를 즉시 원격 삭제할 수 있다고 주장하지 않습니다.
3. 이벤트 로그에는 철회 참여자의 **가명 ID와 순번**만 남습니다. 이것도 개인과 연결될 수 있는 정보이므로 민감하게 다루어야 합니다.
4. 실제 운영에 필요한 신원 검증, 사용자·기관별 동의 관리, 지속성, 상호 인증, 동시성/원자성, 암호화, 장애 복구, 감사 독립성, 데이터 삭제 증명은 **구현되지 않았습니다**.
5. 본 실험에서의 중앙 `ConsentStore` 공유는 결정론적 모의 권한 서비스입니다. 여러 컴퓨터/데이터센터가 실제로 합의하는 구현이 아닙니다. 네트워크 분할 상태에서 최신 철회를 알 수 없으므로 **신선한 권한 확인이 안 되면 전송을 멈추는 가용성-안전성 선택**이 필요합니다.
