# NEXION v0.2.3 — 로컬 SQLite 동의 철회·메시지 원자성 실험

기준일: 2026-11-13. 실제 장비, 외부 사용자, 외부 네트워크와 연결하지 않습니다.

## 검증 가능한 결함

이전 버전에서 `send_peer_message()`는 참여자 상태를 확인한 뒤, 실제 메시지를
DB에 기록하기 전까지 별도 트랜잭션을 확보하지 않았습니다. 그러면 다른 SQLite
연결의 철회 작업이 사이에 완료될 수 있었습니다. `withdraw()`도 동일한 패턴으로
자격 정보를 확인한 뒤 DB 트랜잭션을 시작해, 동일 동의의 중복 철회가 성공할
여지가 있었습니다.

## v0.2.3 수정

- 메시지 전송과 철회 모두 `BEGIN IMMEDIATE`로 **검증 전에 쓰기 예약 잠금**을 확보합니다.
- 사용자의 현재 인증·참여 범위 검증과 메시지 INSERT 또는 메시지 DELETE·인증 토큰 무효화를 하나의 SQLite 쓰기 트랜잭션에서 처리합니다.
- 전송이 먼저 커밋되면 뒤이은 철회가 저장 메시지를 삭제합니다. 철회가 먼저
  커밋되면 후속 전송 검증에서 거부됩니다.
- 실패한 인증/범위 검증은 자동 롤백되어 DB를 잠금 상태로 남기지 않습니다.
- 별도의 로컬 연결 두 개와 `threading.Event` 경합 주입으로 실행 순서를 통제합니다.

## 재현 및 검증

프로젝트 디렉터리에서 Python 3.9+로 실행:

```sh
python -m unittest discover -s tests -v
python -m unittest discover -s tests -p 'test_consent_atomicity.py' -v
python -m nexion.consent_demo
```

- 이전 로컬 코드 + 신규 테스트: 6개 중 2개 실패(동의 철회 중복 승인,
  전송 인증 검증과 철회 간 순서 보장 실패).
- 수정 코드 + 기존 68개와 신규 6개: **74개 통과**.
- 신규 6개 테스트 20회 반복 실행: **20회 연속 통과**.

## 보장하지 않는 것

이 검증은 **같은 SQLite DB 파일을 사용하는 개별 연결 간 원자성**에만 적용됩니다.
SQLite 연결을 공유하는 다중 스레드, 독립 데이터센터 간 동기화, 실제 분산
합의, 로그 유실 복구, 현장 기계 제어, 외부 메시지의 발송 취소를 입증하지
않습니다. 대기 중 메시지는 모의 노드 메모리에 평문으로 보관됩니다.

권한 서버 또는 연결이 없을 때는 이전 버전과 동일하게 전송을 거부합니다.
본 실험은 독립적인 지능·의식·생명체의 탄생을 입증하지 않습니다.
